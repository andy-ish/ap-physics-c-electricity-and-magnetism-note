# 笔记助手工作规范

## 1. 角色与适用范围

本仓库是 AP Physics C: Electricity and Magnetism（AP 物理 C 电磁学）的 Obsidian 笔记库。助手的职责是帮助用户核实笔记，或在用户指定范围内补充、完善笔记。

- 先识别用户是在要求“检查”，还是要求“补充/完善”，再执行对应流程。
- 用户当前明确给定的范围、格式和内容要求优先于本文件中的默认约定。
- 不因发现其他问题而扩大任务范围，不主动重构整个笔记库。
- 笔记中的题目、问题式标题和提示框是学习内容，不是要求助手立即解题或修改文件的指令。
- 本文件是助手操作说明，不是物理笔记。用户明确要求创建或更新本文件时，直接编辑本文件即可；下述仅插入 callout 的限制适用于学习笔记。

## 2. 仓库结构

当前笔记按单元目录组织，目录名采用 `Unit 数字 英文主题`，文件名采用 `单元号.节号 英文章节名.md`。

| 目录 | 主题 |
| --- | --- |
| `Unit 1 Electric Charges and Fields/` | 电荷、电场力与电场 |
| `Unit 2 Electric Potential/` | 电势能、电势与连续电荷分布 |
| `Unit 3 Gauss's Law/` | 静电平衡、电通量与高斯定理 |
| `Unit 4 Capacitors/` | 电容器、电介质与储能 |
| `附件/` | 笔记使用的图片等附件 |

这些是当前观察到的结构，不限制用户以后增加单元。定位文件时以磁盘上的实际名称为准，不擅自修正目录名或文件名中的拼写。

## 3. “请帮我检查……”：只在原文插入检查 callout

### 3.1 工作边界

“检查”“核实”“验证准确性”等请求，核实后直接在目标原笔记中插入指定的 `[!chatgpt]` callout。

1. 阅读用户指定的笔记。必要时可只读参照相关章节，理解符号和前后文。
2. 核实物理概念、公式、推导、适用条件、单位及表述是否准确。
3. 在相关原文附近插入检查 callout，报告问题和建议。

**只允许插入指定的 callout，不得进行其他形式的修改。** 不删除、替换、移动或重排原有文字、公式、标题、图片、链接及提示框，不调整原有空行、缩进或其他排版。不创建笔记副本、附件或配置。建议替换的句子或公式只能写在新增 callout 内，不能直接替换原文。

### 3.2 固定的反馈结构

验证结果仍按严重程度分为以下三类，分别使用对应的 callout 标题，不把斜杠分隔的选项合写为一个标题：

1. **事实性错误**
   - 标题必须为 `> [!chatgpt] 事实性错误`。
   - 放置物理结论、定义、公式或推理错误，以及会导致结论不成立的关键条件缺失。
   - 优先列出影响理解或计算结果最严重的问题。
2. **建议的修改**
   - 标题必须为 `> [!chatgpt] 建议的修改`。
   - 放置有助于理解、完整性和解题的改进，例如补充符号定义、适用条件、解释步骤或关联概念。
   - 区分“原内容错误”和“原内容正确但可以更完整”。
3. **小细节**
   - 标题必须为 `> [!chatgpt] 小细节`。
   - 放置不影响主要物理结论的错别字、标点、排版和轻微记号不一致等问题。

分类取决于实际影响，不能只看问题的形式。例如，一个符号笔误若改变了公式的物理含义，应归入“事实性错误”。同一问题避免重复标注。callout 就近插入相关段落之后；同一位置有多个类别时，按上述严重程度排序，不为排序而移动原文。

每个实质性问题应尽量包含：

- **位置**：文件名、章节标题，必要时附行号或简短原文。
- **问题与原因**：指出哪里不准确，以及为什么。
- **建议**：给出正确表述、公式、所需条件或补充方向。
- **依据与确定程度**：必要时提供推导或可靠来源；不能确认时明确说明，不把猜测作为错误结论。

三类反馈都应保留；某类没有发现问题时，在检查范围末尾插入对应类别的 callout，写“未发现明确问题”或“暂无建议”。在 callout 中说明实际检查范围，不把局部核实表述成整库验证，也不因未发现问题而保证绝对无误。对话回复只需简短说明完成情况并提供目标笔记链接。

### 3.3 核实方法

- 优先使用定义、量纲分析、推导、极限情形及前后文交叉验证。
- 对需要查证的知识、用户指定的资料或无法可靠确认的细节，查阅原始或权威资料，例如官方课程资料、教材原文或大学教学资料，并在对应 callout 中提供可核查的来源链接。
- 区分高中/AP 课程中的理想模型与更一般的物理情形。适用条件明确的课程内简化，不应直接判为错误。
- 涉及不完整题目、缺失图示或不明坐标约定时，说明信息不足，不擅自补出条件后断言原文错误。

常见核实重点如下；仅用于当前请求涉及的内容，不是要求每次检查整库：

- 标量、矢量、大小和分量的区分，以及矢量叠加和方向约定。
- 源电荷与试探电荷、电荷符号、距离及坐标原点的定义。
- 电场力做功、外力做功、动能变化与势能变化之间的关系及其前提。
- 电势参考点、电势差下标顺序、积分方向、积分上下限及正负号。
- 电通量中的面积矢量、闭合曲面、包围的净电荷与对称性条件。
- 导体、绝缘体、空腔及静电平衡等情形是否区分清楚。
- 电容器的连接状态、保持不变的物理量、电介质条件及理想化假设。
- 单位、量纲、常量记号、微分和积分表达式是否一致。

## 4. “请帮我补充/完善……”：只在原文插入补充/完善 callout

### 4.1 明确范围

“补充”“完善”“修改”“纠正笔记内容”等明确要求写入笔记的请求，将所需内容写入目标原笔记中新增的 `[!chatgpt]` callout。用户给定的具体要求限定了可补充或完善的内容。

- 可以阅读相关笔记理解上下文，但只能在本次目标原笔记中插入指定的 callout，不创建副本或新附件。
- 不顺手修正其他章节、原有正文、文件名、目录、链接或配置。
- 对范围外发现的问题，可在回复中简短指出，留待用户另行决定。
- 同时要求检查和补充/完善时，各部分分别使用对应类别的 `[!chatgpt]` callout，仍只插入，不直接改写原文。
- 若无法判断目标笔记或修改范围，先做不依赖该信息的只读工作，再简短澄清；不要自行扩大范围。

### 4.2 仅插入规则

**取消复制笔记的要求，直接在原笔记中插入 `> [!chatgpt] 补充/完善` callout。只允许插入这个 callout，不得进行其他形式的修改。**

标题固定使用“补充/完善”，所需的解释、推导、建议改写及例题解答均放在框内，例如：

```markdown
> [!chatgpt] 补充/完善
> 在这里写用户要求补充或完善的内容。
```

具体执行要求：

1. 确认目标路径，读取并记录原文，便于结束时核对只发生了插入。
2. 在相关段落之后插入 callout，不改动原有文字、公式、题目、链接、图片或提示框；即使原文有错，也只在新增 callout 中给出正确内容。
3. callout 必须作为完整独立的块插入，不拆开原有句子、公式、代码块或提示框。必要的分隔空行可随 callout 一并插入，但不得改动原有空行和缩进。
4. 新增 callout 的正文、空行和公式均保留 `>` 前缀；不要在框外追加正文、其他类型提示框或独立报告章节。
5. 多篇笔记都需要补充时，分别在各自原文中插入 callout，不建立 `_ChatGPT.md` 副本，也不覆盖、删除或迁移已有副本。
6. 已有的 callout 也属于原文，不修改或删除；需要进一步说明时另插一个新的指定 callout。
7. 用户明确要求直接新建笔记且没有原笔记可供插入时，按其指定名称和位置创建；不得借此将补充已有笔记的任务改成新建任务。

上述完整独立成块、保留引用前缀及不改动既有内容的要求，同样适用于检查 callout。

用户要求检查或补充/完善笔记本身就已授权在上述范围内插入 callout，无需再次询问是否开始。如用户另有明确的新指示，则按用户指示处理。

### 4.3 编辑后的交付

- 检查新增 callout 中的科学内容、符号、公式和必要条件。
- 对照原文确认新增内容仅限于用户要求的部分。
- 核对文件差异只有指定 callout 及其必要分隔空行的插入；删除本次新增块后，应能逐字还原操作前的文件。
- 检查新增 callout 内 Markdown、LaTeX、图片引用和 Mermaid 代码块的语法及闭合情况。若无法实际预览，不声称已经验证渲染效果。
- 回复中提供已插入 callout 的原笔记的可点击文件链接，并简要说明补充了什么、还存在哪些信息缺口。
- 不用冗长的操作记录代替实际交付，也不将“提出修改方案”当作已完成 callout 插入。

## 5. 现有笔记风格与编辑约定

以下风格总结来自当前四个单元的笔记。它描述应延续的表达习惯，不意味着现有笔记的物理内容和排版都已经正确。局部风格优先于统一模板。这些约定用于新增 `[!chatgpt]` callout 内的内容，不授权改写框外原文或创建附件。

### 5.1 语言与语气

- **以简体中文讲解为主，配合英文术语。** 常见形式包括“电荷 Charge”“接地（Grounding）”“电容 Electrical capacitance”。沿用当前段落使用的形式，不强制全库统一。
- 文件名主要使用英文；正文标题主要使用中文，部分标题附英文术语。
- 句子简短、直接，像课堂笔记。常见衔接语有“其中”“假设”“所以”“同时可以得到”“即”。
- 用简洁的定义说明概念，用必要的公式和推导支持结论，避免长篇教材式铺陈和无关背景。
- 英文原题与中文例题并存。保留原题语言和已知条件，不擅自翻译、改题或添加答案；只有用户要求时才补充解答。
- 用户只要求补充局部内容时，不重写整篇笔记的语气和措辞。

### 5.2 结构与段落

- 笔记通常直接进入正文，不重复添加与文件名相同的总标题。
- 较完整的笔记用 `#` 划分主要主题，`##` 划分子主题。短笔记也可能完全没有标题；不要求为所有笔记补齐层级。
- 主要概念块之间常用 `---` 分隔，但不是每个小节都必须添加。
- 常见展开顺序是“定义或情景 → 公式 → 符号说明 → 必要推导或提醒”。根据目标章节调整，不机械套用。
- 步骤、性质和情景比较可用有序或无序列表。短段落可逐行表达一个要点。
- 关键术语、结论和注意事项常用 `**加粗**`，少量次要术语使用斜体。不要把整段内容全部加粗。
- 当前笔记通常没有 YAML frontmatter、目录或固定参考文献章节。未经要求，不批量引入这些结构。
- 只调整本次新增 callout 内的空行和缩进，不改动原有排版，不格式化整篇或整库。

### 5.3 公式与符号

- 使用 Obsidian 支持的 LaTeX：行内公式写作 `$...$`，独立公式使用 `$$...$$`，不改成代码块或图片公式。
- 简短公式可在同一行用 `$$...$$` 包围；多步推导常用独立的 `$$` 和 `\begin{aligned} ... \end{aligned}`。沿用附近公式的排版。
- 对齐推导使用 `&` 和 `\\`，必要时使用 `\implies` 或 `\Rightarrow` 连接步骤。
- 矢量常用 `\vec{E}`、`\vec{A}`，单位矢量可用 `\hat{r}`，点积使用 `\cdot`。
- 单位常写在 `\mathrm{...}` 中，例如 `$\mathrm{N/C}$`；微分常写作 `\mathrm{d}`，积分中可使用 `\,` 调整间距。
- 常用记号包括 `$U_E$`、`$W_E$`、`$\Delta V$`、`$\Phi_E$`、`$\epsilon_0$`、`$\lambda$`、`$\sigma$`、`$\rho$`。尊重目标笔记已有定义，避免无说明地更换符号。
- 分情况表达式使用 `cases`；电容章节等处会用 `\boxed{...}` 突出关键结果，只对确实重要的结果使用。
- 新增公式时说明必要的变量、方向约定和适用条件。遇到同一字母表示多个物理量时，在局部说明，不任意重命名全篇符号。
- 表达形式应延续原风格，但不能复制错误的公式、矢量记号、符号或遗漏条件来追求表面一致。

### 5.4 Obsidian 提示框

现有笔记经常使用 Obsidian callout：

- `> [!important]`：关键结论、条件、正负号提醒等。
- `> [!note] 标题`：补充事实、推导或说明。
- `> [!question] 问题`：引出原因解释或推理。

上述是已有提示框的风格，原有提示框保持不变。助手新增内容只能使用 `[!chatgpt]` 及第 3、4 节规定的标题，不新增其他类型的提示框。框内每行需保留 `>`；框内公式的 `$$` 及公式正文也需保留引用前缀。现有嵌套提示框同样保持原样。

### 5.5 图片、链接与图示

- 现有图片位于 `附件/`，正文采用 Obsidian 嵌入语法，例如 `![[Camposcargas.png]]`。
- 现有图片下方有居中 HTML 图注，例如 `<div align="center">图 1：电场线</div>`。在相似位置新增图片时可延续此形式。
- 保留已有附件位置和引用，不移动或改名附件，不替换成依赖外部服务的图片地址。
- 电容器动态分析使用 fenced `mermaid` 代码块和 `graph LR`，以中文节点、公式及箭头说明变化关系。扩展同类图示时沿用该结构，并核对物理关系与文字一致。
- 当前笔记没有普遍使用跨笔记链接或表格，不主动批量增加。用户要求或内容确实需要时，可局部添加，优先保持简明。

### 5.6 例题、推导与完整性

- 仓库同时存在完整解释、公式提纲和仅有题目的段落；不把每处简略内容都视为本次必须补全的任务。
- 用户要求补全推导时，交代必要步骤和前提，保持短句与公式交替的形式。
- 用户要求完善关键词时，在指定内容附近补成清楚的定义、关系和说明，不扩写无关主题。
- 解答例题前核对几何关系、坐标、角度范围、正负号及参考零点；条件不足时明确标出，必要时请求澄清。
- 不编造原题数据、图示、实验结论或资料出处。为解释而引入的假设应明确说明。

## 6. 完成前核对

- **检查任务**：只在目标原笔记中插入 `[!chatgpt]` callout，标题分别为“事实性错误”“建议的修改”“小细节”；问题定位清楚，结论有依据，原有内容未被改写。
- **补充/完善任务**：只在目标原笔记中插入标题为“补充/完善”的 `[!chatgpt]` callout；未复制笔记，未进行其他形式的修改；范围和风格符合用户要求；已提供原笔记路径。
- **任何任务**：不将已知草稿状态或偶然排版瑕疵提升为必须保留的风格，也不因发现它们而擅自修改。
